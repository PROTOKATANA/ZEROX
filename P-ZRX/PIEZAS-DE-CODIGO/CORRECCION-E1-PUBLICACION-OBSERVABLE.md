## Problemas confirmados por revisión Rust

1. `difundir_anuncio`/`difundir_tx` solo confirman encolado; el bucle silencia fallos de `gossipsub.publish`. La prueba negativa de presupuesto podría pasar si el anuncio nunca salió. Añade al `Comando::Difundir` una respuesta `oneshot` con resultado del intento de publicación del bucle. Haz que los dos métodos públicos esperen esa respuesta y devuelvan error si gossipsub rechaza el envío local. Usa el error de red existente con una descripción honesta si basta; **éxito de publish solo acredita aceptación local por gossipsub, nunca entrega ni validez DAG**. Mantén el bucle no bloqueante. Un tema defensivamente rechazado debe responder `Err`, no dejar esperando el oneshot. Ajusta tests: antes de afirmar `Ignorar` por presupuesto, exige que la primera publicación del emisor devuelva `Ok`; después de liberar, publica un anuncio **distinto** y comprueba callback. Si ya existe una prueba que funciona así tras el cambio, no la dupliques.
2. `servicio.rs` dice que la API tipada impide publicar anuncios sin validación. Es falso: `AnuncioCompacto` se puede construir con sello cero y PoAS default, como en el propio test. Corrige la documentación: la API fija **formato y tema**, no certifica validez; futuro productor debe llamar solo tras admisión DAG. En recepción se mantiene `Ignorar` por default. Corrige frases de tests que confundan encolar/publicar/entregar.
3. `ZxBehaviour::gossipsub` y `parametros` son campos `pub`, y se podrían cambiar después del constructor mientras `ManejoRed` conserva otra copia de los temas. Reduce a `pub(crate)` si no rompe `zx-node` ni los tests; si otro campo público permite igual desincronización, delimita explícitamente la garantía a la ruta construida por el nodo. No agregues más envoltorios ni comportamientos.
4. Añade o ajusta una prueba de dos nodos para `/txs/1` que demuestre el callback real y que el canal de bloques `/2` no lo recibe; usa el mismo `dos_conectados` y una tx serializada válida si el dispatcher lo exige. El test de `behaviour` ya comprueba ausencia de suscripción `/blocks/1`; no crees un emisor libre de temas solo para probarlo.
