# Corrección C2 · hash sin heap e índice U2 incoherente

Ejecutor: DeepSeek Harness `deepseek-v4.1-flash`, esfuerzo `high`. Leer [ORDEN-C2-IDENTIDAD-EXACTA.md](ORDEN-C2-IDENTIDAD-EXACTA.md), este archivo y el diff C2 actual. No hacer commit ni push. Conservar toda la igualdad literal y los tests de U2/U3 ya entregados.

## Hallazgos de revisión independiente

1. `IdentidadGhostdag::Hash` llama `IdentidadTicket::bytes_canonicos()` y reserva un `Vec` por consulta de `HashSet`; `Ord::cmp` reserva dos `Vec` por comparación. U3 usa `HashSet` en la ruta Kernel y la referencia ordena acumuladores. La identidad debe seguir siendo la tupla exacta, pero no debe asignar heap por hash/comparación. `IdentidadTicket` mide 82 B canónicos con anchuras de `firmante/identidad.rs`; no cambies ese esquema ni `huella()` del registro D3. Implementa una vía **sin heap**: preferiblemente un método que devuelva `[u8; 82]` en la pila o `Hash`/`Ord` campo a campo en el módulo `firmante/identidad.rs`; la modificación de este archivo está justificada exclusivamente para compartir los campos privados sin abrirlos. `IdentidadGhostdag::Eq`, `Hash` y `Ord` deben ser consistentes. El `Display` de error no está en el camino de aceptación y puede conservar su huella diagnóstica.
2. `AlmacenGhostdag::pasado_contiene_ident` devuelve `false` si `idents[raiz]` o `anc[raiz]` faltan. Cambiar a `Result<bool, ConsensusError>` y propagar `GhostdagIncoherente` antes de toda mutación. Si en la iteración del pasado falta `idents[x]`, también falla explícitamente; nunca convertir incoherencia interna en ausencia de duplicado U2.
3. El comentario del nuevo test `identidades_distintas_con_misma_proyeccion_no_disparan_u2_ni_u3` dice que la implementación previa proyectaba los primeros ocho bytes de la clave pública. Eso no está demostrado: la API previa recibía un `u64` libre, sin proyección definida. Redactar el test como **contraejemplo de cualquier proyección artificial de ocho bytes elegida para el test**; no atribuir esa proyección a la implementación histórica. Comprobar el color de la hermana `S` de forma directa, no solo que una lista de colores no contiene `RojoU3`.

## Pruebas y límites

- Test significativo de incoherencia interna con estado fabricado **solo dentro del módulo de tests privado**: quitar una identidad o ancestro después de insertar un padre y comprobar que U2 devuelve `GhostdagIncoherente` y no muta más el almacén. Si tocar campos privados desde un test externo es imposible, poner este test en `ghostdag.rs` bajo `#[cfg(test)]`.
- Test de consistencia `Eq`/`Hash`/`Ord` para tickets distintos que comparten prefijo y para un ticket idéntico; `Hash` igual cuando `Eq` igual, `cmp == Equal` si y solo si `Eq` igual. El objetivo es prevenir una optimización que introduzca colisión semántica; una colisión de hash ordinaria es aceptable porque `HashSet` comprueba `Eq`.
- Repetir suite GHOSTDAG, `cargo test -p zx-consensus --locked`, Clippy `-D warnings`, formato y los guardianes CI. Informar cualquier archivo adicional modificado, incluido `firmante/identidad.rs`.
- Documentar el límite restante: `blue_idents` copia una colección creciente por bloque y U2 recorre ancestros. **No** activar este almacén en la ruta de red ni marcar C2 cerrada hasta diseñar el índice compartido/acotado y fuente causal. No intentar resolverlo en esta corrección ni inventar una cota.
