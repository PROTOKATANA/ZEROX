## 1. Retirar reemplazo inseguro

`reemplazar_sector_en_disco`/`publicar_par` hacen varios `rename` entre `.bak` y final. Un corte tras mover solo uno deja el par anterior inaccesible; `abrir` no recupera `.bak`. Eliminar **por completo** el API de reemplazo, su `bool`, las rutas `.bak` y `restaurar`. D1 puede ofrecer solo `plotear_sector_en_disco`, que rechaza una ruta con sector o metadata existente con `ParcelaExistente`; el orden original exige no sobrescribir sin una operación segura, pero no exige exponer reemplazo en 0.0.1. No afirmar atomicidad de par: dos renombrados pueden dejar un par incompleto tras corte, y `abrir` debe seguir fallando explícitamente.

Evitar carreras entre dos escritores del mismo destino: antes de plotear, adquirir un fichero `<ruta>.lock` con `OpenOptions::create_new(true)`; si ya existe, error tipado `ParcelaEnUso` (sin eliminar el lock de otro). Retener el guard de lock durante ploteo, escritura, dos renombrados y `sync_all` del directorio; al soltarlo, eliminar **solo el lock propio**. Si un proceso muere, el lock huérfano hace fallar cerrado; documentar recuperación manual, no borrarlo automáticamente. Después de adquirir el lock, comprobar de nuevo ambos destinos. No borrar `.tmp` preexistentes a ciegas: un lock huérfano debe detener la función antes de cualquier limpieza, y con lock propio los `.tmp` antiguos pueden señalar un corte anterior; rechazar con error tipado o usar nombres nuevos sin sobrescribirlos. Preferir `create_new` para temporales y evitar que `rename` sobrescriba un destino creado por fuera; si no puedes garantizar esta última propiedad de forma portable, dejarla documentada como precondición de directorio de datos exclusivo y comprobada antes de cada rename. No añadir una falsa promesa de transacción entre dos archivos.

Actualizar el test que hoy llama `reemplazar_sector_en_disco`. Probar que una segunda llamada al ploteo del mismo destino devuelve `ParcelaExistente` **y** el par previo sigue abriendo con exactamente la misma huella y auditoría. Probar dos escritores concurrentes al mismo destino mediante barrera o una prueba del lock preexistente: el segundo falla `ParcelaEnUso` sin tocar los archivos del primero. Conservar tests de corrupción, par incompleto, plotter fallido y auditoría upstream.

## 2. Hash incremental sin reserva proporcional al sector

`huella_de_region` usa `vec![0u8; longitud]`, donde `longitud` viene de `sector_size(pieces_in_sector)` y `pieces_in_sector` es `u16`; un metadata de archivo sparse puede forzar una reserva enorme al abrir. Cambiar a lectura en fragmentos de memoria fija (p. ej. buffer de 64 KiB elegido de implementación, **no consenso**) y `blake3::Hasher` incremental, con `read_exact`, aritmética comprobada y propagación de EOF/E/S. Comparar la huella BLAKE3 resultante con la del cuerpo. Usar la dependencia `blake3 = { workspace = true, optional = true }` habilitada por `farmer`; no cambiar la versión raíz. El hash en escritura puede seguir sobre el `Vec` de salida del plotter, que ya existe; no duplicar un segundo sector completo en memoria.
